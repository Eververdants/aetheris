# aetheris v2.2 Single-Application Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn aetheris from four binaries into one `aetheris.exe` with subcommands, a resident tray UI, automatic elevation + first-run config, and close out the carried v2.1 hardening debt.

**Architecture:** A new `crates/aetheris-bin` crate hosts the single binary; the four existing bin mains become in-crate mode modules dispatched from one `main.rs`. `aetheris-core` stays the untouched engine lib. The UI mode gains a tray icon and drives the service mode (a separate elevated process) over the existing pipe.

**Tech Stack:** Rust, windows 0.62.2 (`Win32_UI_Shell` for tray), existing `aetheris-core::ipc`, serde/bincode. Target Windows 10 1809+ / Win11.

## Global Constraints

- **No async runtime** anywhere.
- **Equivalence by construction:** the restructure (Task 1) is a pure move — no behavior change. The existing 85+ core tests must stay green unchanged (they are the equivalence proof).
- **Service stays headless + zero-overhead:** the engine hot path and `aetheris-core` are untouched except where a task explicitly says so.
- **Security:** SaveConfig stays elevated-only; pipe DACL stays GRGW+SYSTEM; UAC is used for elevation, never self-elevating silently without a prompt.
- **One exe, one name:** the release artifact is `aetheris.exe`; internal process launches (`aetheris service` via UAC, `aetheris overlay` via CreateProcess) resolve the exe from `current_exe()`.
- Dependencies locked; every new windows feature passes cargo-deny. Every task ends green + committed.

- Test: build + existing suite green + manual subcommand smoke

**Interfaces:**
- Consumes: the four existing `main.rs` files (moved verbatim into mode modules).
- Produces:
  - `crates/aetheris-bin/src/main.rs` (declare the mode modules, dispatch):
    ```rust
    mod mode_cli;
    mod mode_overlay;
    mod mode_service;
    mod mode_ui;

    fn main() {
        let args: Vec<String> = std::env::args().skip(1).collect();
        let sub = args.first().map(|s| s.as_str()).unwrap_or("ui"); // no-arg = ui
        let code = match sub {
            "service" => mode_service::main(args[1..].to_vec()),
            "ui"      => mode_ui::main(args[1..].to_vec()),
            "overlay" => mode_overlay::main(args[1..].to_vec()),
            "cli"     => mode_cli::main(args[1..].to_vec()),
            "--version" | "-V" => { println!("aetheris {}", env!("CARGO_PKG_VERSION")); 0 }
            other => { eprintln!("usage: aetheris [service|ui|overlay|cli] ..."); eprintln!("unknown subcommand: {other}"); 2 }
        };
        std::process::exit(code);
    }
    ```
  - Each `mode_*.rs` exposes `pub fn main(args: Vec<String>) -> i32` — the old `fn main()` body, with `std::process::exit(...)` calls replaced by `return code;` (or keep exit — but prefer returning the code so the dispatcher exits once). `mode_service` returns 0/1; `mode_cli` returns 0/1/2; `mode_ui`/`mode_overlay` return 0 on clean exit, 1 on error.
  - `crates/aetheris-bin/Cargo.toml` = union of the four bins' deps: `aetheris-core` (path 1.0.0), `ctrlc`, `windows` with the union of all features, `serde`, `bincode` (from cli's core re-export? cli only needs core — check each bin's Cargo.toml and merge). `#![windows_subsystem = "windows"]` applies to the whole binary — but `service`/`cli` modes write to stderr! **Fix:** do NOT set `windows_subsystem` at the crate level; instead use the `subsystem` per-UI behavior: since a console app shows a console for UI/overlay too, accept a console window for `ui`/`overlay` (cosmetic, matches v2.1) OR call `FreeConsole()` at the top of `mode_ui`/`mode_overlay` when launched with a console. **Decision:** keep the binary console-subsystem; `mode_ui` and `mode_overlay` call `FreeConsole()` on startup (the GUI modes detach from any console), while `service`/`cli` keep stderr. Document this in the dispatcher.

- [ ] **Step 1: Create `crates/aetheris-bin/Cargo.toml`** — merge the four bins' `[dependencies]`; add `[[bin]] name = "aetheris" path = "src/main.rs"`.
- [ ] **Step 2: Move the four mains into mode modules** — copy each `main.rs` body into its mode module as `pub fn main(args: Vec<String>) -> i32`, replacing `fn main()` and `std::process::exit(code)` with `return code`. Each mode parses its own args from the passed slice (strip the subcommand already handled by the dispatcher). For `mode_ui`/`mode_overlay`, add `let _ = unsafe { windows::Win32::System::Console::FreeConsole() };` as the first statement.
- [ ] **Step 3: Write the dispatcher + register the crate** — root `Cargo.toml` members = `["crates/aetheris-core", "crates/aetheris-bin"]`; delete the four old bin crates.
- [ ] **Step 4: Build + equivalence check**

Run: `cargo build --workspace` (green), `cargo test -p aetheris-core` (all 85+ pass unchanged — the equivalence proof).
Run: `target/debug/aetheris cli` with no service → the old cli behavior (error + exit 1); `target/debug/aetheris --version` → `aetheris 1.0.0`; `target/debug/aetheris badcmd` → usage + exit 2.
> Note: `cli` and `service` share the same binary now; `mode_cli`'s `std::env::args` still sees the full argv — parse from the passed slice, not `env::args`, so the subcommand is not double-consumed.

### Task 2: Tray UI (Shell_NotifyIcon)

**Files:**
- Modify: `crates/aetheris-bin/src/mode_ui.rs`
- Modify: `crates/aetheris-bin/Cargo.toml` (add `Win32_UI_Shell`)
- Test: manual (tray icon appears; minimize-to-tray; menu actions)

**Interfaces:**
- Consumes: the existing dialog `run()` (the UI already has a message loop + window); `client_call`, `Request::GetState`, `Response::State`.
- Produces:
  - `const WM_TRAYICON: u32 = WM_APP + 2;` — `Shell_NotifyIconW(NIM_ADD, ...)` on window creation, `NIM_DELETE` on destroy; `NOTIFYICONDATAW { uFlags: NIF_MESSAGE|NIF_ICON|NIF_TIP, uCallbackMessage: WM_TRAYICON, hIcon: LoadIconW(...), szTip: "aetheris" }`.
  - In the wndproc `WM_TRAYICON` handler: left-click (`lparam == WM_LBUTTONUP`) → `ShowWindow(hwnd, SW_SHOW)` + `SetForegroundWindow`; right-click → `TrackPopupMenu` with the tray menu.
  - Tray menu items (via `CreatePopupMenu` + `AppendMenuW`), ids:
    - `IDM_START_SERVICE` → `ShellExecuteW(runas, "aetheris.exe service")` — but the exe is `current_exe()`; use `ShellExecuteW(None, w!("runas"), exe_path, w!("service"), None, SW_SHOW)`.
    - `IDM_STOP_SERVICE` → send `Request::ReloadConfig`? No — stop needs a `Stop` over the pipe. **Add `Request::StopService`** (new IPC) → service main loop breaks → process exits (graceful, `exit_game_mode` on Stop). If the pipe is down, log "service not running".
    - `IDM_TOGGLE_OVERLAY` → `Request::ToggleOverlay` (new IPC) → service's main-loop arm runs the existing `launch_overlay`/toggle logic (move the hotkey handler's toggle into a shared fn callable from both `ToggleOverlay` hotkey and this message).
    - `IDM_OPEN_UI` → `ShowWindow(SW_SHOW)` + `SetForegroundWindow`.
    - `IDM_EXIT` → `DestroyWindow` (UI process exits; the service keeps running).
  - Minimize-to-tray: on `WM_SIZE` with `SIZE_MINIMIZED`, hide the window (`ShowWindow(SW_HIDE)`) instead of minimizing.
  - Service-status icon: on each tray refresh (a `SetTimer` every 5 s in the dialog loop, or reuse the existing status refresh), probe `GetState`; set a green/gray icon (two `HICON` from `LoadIconW`-like handles) via `NIM_MODIFY`.

- [ ] **Step 1: Add `Request::StopService` + `Request::ToggleOverlay` to core** (in `crates/aetheris-core/src/ipc.rs`):

and the service's IPC thread arms:
- `Request::StopService` → `let _ = ipc_tx.send(ServiceMsg::Stop); Response::Reload("stopping".into())`.
- `Request::ToggleOverlay` → `let _ = ipc_tx.send(ServiceMsg::ToggleOverlay); Response::Reload("toggled".into())`.
Update `IpcServer` test handlers + the CLI's exhaustive match. Add core tests for the two new arms (roundtrip handler returns the right Response).

- Modify: `crates/aetheris-core/src/config.rs` (a `default_config_str()` helper + `default_config_path()`)

**Interfaces:**
- Consumes: `Config`, `Service`, `client_call(GetState)`.
- Produces:
  - `aetheris_core::config::default_config_path() -> PathBuf` = `%PROGRAMDATA%\aetheris\aetheris.toml`.
  - `aetheris_core::config::default_config_str() -> String` = the current `aetheris.toml` content (commented examples).
  - `mode_service`: if no `--config` given, use `default_config_path()`; if the file doesn't exist, write `default_config_str()` before `Config::load`. (The service is elevated, so the PROGRAMDATA write succeeds.)
  - `mode_ui` on startup:
    - Probe `client_call(GetState)`. If Err (service down): `ShellExecuteW(runas, current_exe(), "service", ...)` to UAC-launch the service, show a status line "starting service…", and retry the probe a few times over ~5 s.
    - Auto-open: the dialog already creates + shows the window at startup (keep).
  - Save-elevation: if `mode_ui` is not elevated and a Save fails with "requires elevation", prompt to relaunch as admin: `ShellExecuteW(runas, current_exe(), "ui", ...)` then exit 0 (the new elevated instance takes over). Detect elevation via `GetTokenInformation(TokenElevation)` on the process token.
